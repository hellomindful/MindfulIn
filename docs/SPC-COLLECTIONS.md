Eleven collection routes on mindfulin.com share one template, one stylesheet and one manifest.

## Files

- `js/spc-collections.json`: the manifest. Every collection and every sellable item lives here once.
- `js/spc-render.js`: reads the manifest and renders the page body into `#spc-root`.
- `css/spc.css`: collection styles, scoped to `.spc-page`.
- `<slug>.html`: page shells with the shared header, footer and SEO metadata. Generated by `docs/spc-build-pages.mjs` from `media.html`.
- `docs/spc-crosswalk.csv`: one row per collection and item, for the Airtable catalog. Airtable stays the authoritative record.

## Item statuses

- `LIVE`: verified product, price, checkout and fulfillment. Shows a price and a button.
- `PREVIEW`: a real asset or prototype. Shows with a "Preview, not for sale" label and no button.
- `IN_PRODUCTION`: needs a supplier, price or fulfillment. Never shown.
- `CATALOGED`: a concept or an empty storefront. Never shown.

## Add a product

1. Confirm the product is live at its own checkout (Ecwid, Etsy/Printify, Gumroad, Mindful Offers, KDP). Do not create a new checkout here.
2. Add one object to `items` with its real `url`, `price` as listed at the source, and `status: "LIVE"`.
3. Under `placements`, map each collection slug to a group key that exists in that collection (for example `"mantraspc": "pod"`). One item can appear in several collections without duplicating the checkout.
4. Update `lastVerified`. No HTML changes are needed.

Reserved modules: the `pod` group on /mantraspc and /stickeredspc and the `shop` group on /sensoryspc, /breathspc and /affirmspc render automatically once a LIVE item is placed in them.

## Add a collection

Add an object to `collections`, then run `node docs/spc-build-pages.mjs` from the repo root to create its shell.

## Rules

- Never invent prices, stock, images, reviews or payment links.
- Prices and buttons only for `LIVE` items.
- Do not change prices or checkout links here; change them at the source, then update the manifest.
